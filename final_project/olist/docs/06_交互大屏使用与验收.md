# Olist交互大屏使用与验收

大屏由Dash和Plotly实现，所有指标与图形均由Python根据本地清洗表生成。不依赖Power BI、Tableau或Excel图表。页面沿用深蓝主题，提供真实筛选联动，而非静态截图。

当前开发、数据核对和HTTP回调验证已完成。本机服务已启动过；若服务停止或电脑重启，需要重新运行启动命令。当前自动化环境仅提供MCP Apps表面，未连接可操作的普通浏览器，因而尚未进行真实浏览器点击、布局验收和页面截图。这一限制不等同于页面已通过视觉检查。

## 启动方法

在项目根目录运行：

```powershell
python -m pip install -r requirements.txt
python run_dashboard.py
```

在浏览器打开 http://127.0.0.1:8050/ 。服务默认只监听本机，未发布到外网。端口被占用时可运行`python run_dashboard.py --port 8051`并打开相应地址。终端按Ctrl+C可停止服务。

已有清洗数据即可启动，无需每次重新下载或运行全部分析。缺少清洗数据时先执行`python run_all.py`；一键分析只验证大屏，不启动长期运行的服务。

## 组件及联动

| 组件 | 操作或展示 | 联动行为 |
|---|---|---|
| 购买日期范围 | 起止日期，按购买时间，包含结束日 | 更新所有指标、图形、明细和导出 |
| 收货州多选 | 可搜索州代码，如SP | 按客户收货州筛选，不代表卖家所在地 |
| 商品类别多选 | 常见类别中文名及原始类别名 | 仅统计所选商品金额，涉及订单去重 |
| 商品金额KPI | 万BRL，不含运费 | 随三个筛选更新 |
| 涉及订单数KPI | 订单去重，并展示客户数 | 随三个筛选更新 |
| 客单价或订单平均选品金额KPI | BRL/涉及订单 | 品类筛选时自动更换名称和口径 |
| 配送逾期率KPI | 有效配送样本逾期比例 | 随涉及订单集合更新，显示分母 |
| 月度趋势图 | 商品金额，悬停查看 | 重新汇总筛选后的商品金额 |
| 商品贡献图 | 金额前8个类别 | 按筛选范围重新排序 |
| 收货州金额图 | 金额前8个州 | 按筛选范围重新排序 |
| 配送与评分图 | 按期和逾期订单平均分 | 涉及订单去重，悬停查看数量及低评分比例 |
| 订单明细 | 按购买时间倒序展示前30单 | 同时展示所选商品金额与整单金额 |
| CSV导出 | 当前筛选全部涉及订单 | 保留中文BOM编码，金额与KPI一致 |
| 重置筛选 | 恢复日期与全部州、品类 | 重新计算并恢复全样本 |

因此组件数量超过老师要求的至少6个，且筛选、KPI、图表、明细和导出通过Python回调联动。页面锚点导航只用于滚动浏览，不作为额外联动组件计数。

## 筛选口径

1. 基础销售样本为2017年1月1日至2018年7月31日购买、最终已交付且通过金额质量检查的订单。
2. 金额以整数分计算，显示时换算BRL或万BRL。不含运费，也不代表利润。
3. 筛选品类后，只加总所选品类的商品金额。订单计数按涉及订单ID去重，同一订单包含两个选中品类时只计一次。
4. 品类筛选后的配送与评价反映涉及订单的整单结果，不能理解为所选商品本身的配送或因果效果。整单金额另列在明细中，不混入所选金额KPI。
5. 配送逾期按签收自然日晚于预计自然日定义；缺失签收或预计日期的订单不进入配送分母。评分图仅使用有有效配送及评分的订单。
6. 日期可选择部分月份，因此大屏不直接给出未经对齐的同比或环比增速。历史预测目标与销售口径不同，本页面不把固定预测结果伪装成全局筛选联动结果。
7. 暂无数据或暂无有效配送时，图形显示无数据提示，相应平均值或比例显示“—”，不把缺失结果当成0。
